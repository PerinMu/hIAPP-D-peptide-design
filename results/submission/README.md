# Candidate result files

`results.csv` is the machine-readable final candidate list generated by
`bash run.sh`. It is UTF-8 encoded and contains exactly 12 candidates ordered by
`final_rank`. `results.xlsx` is a formatted convenience mirror of the same
table; `results.csv` is the authoritative regenerable output.

`run_metadata.json` is generated on every run and is intentionally
not versioned because it contains the execution timestamp, platform, and current
repository revision. It records input/output, screening-table, generation-code
and structure SHA256 hashes for that run. Code hashes distinguish local edits even before a commit.

After generation, run the following from the repository root to compare against
the deposited CSV/Excel, screening tables, review tiers and recorded hashes:

```bash
python scripts/validate_submission.py --output-dir results/submission
```

## Fields

| Content | Columns |
|---|---|
| Candidate identifier | `candidate_id`, `final_rank` |
| Track | `track` |
| Candidate sequence/SMILES | `d_peptide_sequence`, `l_design_sequence`, `smiles` |
| Structure | `structure_file`, `structure_format`, `coordinate_unit`, chain IDs, protonation and hydrogen-representation fields |
| Key predicted indicators | `ptm`, `iptm`, `min_ptm_iptm`, confidence/affinity heads, relative composite scores, physicochemical tendencies |
| Model and version | `model_and_version` |
| Notes/status | `experimental_status`, `measured_activity`, `remarks` |

Relative scores range from 0 to 1; sequence-property tendency scores range from
0 to 100. They are unitless ranking aids. Missing experimental values use the
literal `not_measured`, not zero. Affinity-head outputs are not presented as
physical binding-affinity units.

Every `structure_file` is an mmCIF complex in angstrom coordinates. The target
is polymer chain A and the stereochemical peptide ligand is non-polymer chain X.
The deposited predictions contain heavy atoms only, with no explicit hydrogens;
the protonation state is therefore reported as `not assigned`. The
target-template and intended-region columns document the hIAPP input context.
The model field records BoltzGen/BoltzIF 0.2.0 and the recovered Boltz 2.2.1
environment; checkpoint hashes and the evidence boundary are documented in the
Model Card and `docs/PRODUCTION_ENVIRONMENT.md`.
